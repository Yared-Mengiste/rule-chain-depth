# B2: fixed EntailmentBank comparison

B2 contains **42 checked-in EntailmentBank Task 2 worlds**, six at each annotated
graph depth 1–7. Each retains **25 original sentences**, including distractors,
and one supplied hypothesis. PLN-RAG, normal RAG, and full context run on the
same worlds: **126 system/world records** for the complete comparison.
Full context uses the same explanation prompt and generation settings as RAG,
with all 25 sentences, helping inspect retrieval limitations. No model training,
dataset download, or split-selection step is part of normal use.

## Commands

Run from this repository with Python 3.10 or later:

```sh
python3 -m b2 validate
python3 -m b2 benchmark --prepare-only
python3 -m b2 benchmark --container pln-rag-pln-rag-1
```

Validation checks the entire bundle offline. Preparation writes a new plan with
the selection, effective settings, source hashes, and request estimates. It
does not require credentials, sibling repositories, Docker, embeddings, or
network access. A live invocation creates its own run and scores/reports
automatically; there is no saved-plan execution or resume protocol.

Optional small trials use a prefix of the same dataset after validating all 42:

```sh
python3 -m b2 benchmark --container pln-rag-pln-rag-1 --world-limit 2
python3 -m b2 benchmark --systems rag --world-limit 2
python3 -m b2 benchmark --systems full_context --world-limit 2
```

The first two worlds have graph depths 1 and 2; the first seven cover depths
1–7. Runs never resample. `--systems` defaults to `pln_rag rag full_context`.
The installed `b2` entry point provides the same commands; `b1` is preserved.

## Configuration and runtime

This repository's `.env` supplies defaults; inherited environment variables take
precedence for the same variable. Set `OPENAI_API_KEY` there, never in a command
or fixture. `OPENAI_MODEL` accepts `openai/<model>` or `openrouter/<model>`.
OpenRouter also requires `OPENROUTER_PROVIDER`; its endpoint can be configured
with `OPENROUTER_BASE_URL`. The provider is pinned and routing fallback disabled.
All three modes share model, provider, temperature, output limit, and timeout.
The baseline adapter strips only the routing prefix for its direct HTTP request.
Automatic model retries and caches are disabled. Native parser formatting or
query fallback calls remain part of PLN and count against the cap.

PLN defaults to Docker. The launcher inspects the named running container and
starts **one temporary container for the entire selected PLN portion**, using
its immutable image ID with no pull or rebuild. As in B1, the repository is
bind-mounted at the same absolute path and is the working directory. An
`--output-dir` outside the repository gets an additional bind mount at its
absolute path. The two individually inspected parser JSON artifacts, when
present, are mounted read-only; the live application's data volume is not
mounted. The container runs as the launcher's effective UID/GID and is removed
on exit or interruption. There is no worker-code copying or staging.

The container supervisor launches separate Python processes for each world's
learning and query operations. The image's native Python search paths and
SWI-Prolog environment are preserved, so PeTTa and the other image dependencies
remain importable; host dependency paths are not forwarded. Credentials are
forwarded by environment variable name; headers are excluded from audits.
Effective B2 settings travel in the public job, without credential values.
The mounted repository also exposes its `.env`, dataset and reports (see the
input boundary below). B2 never calls the live application's ingest/query/reset
API. Linux host networking reaches Qdrant and Ollama.

The image must have the real canonical PLN parser, DSPy/NL2PLN, PeTTaChainer,
PeTTa/Janus, and SWI-Prolog dependencies. Local mode requires those dependencies
in an existing interpreter. B2 does not install or replace the native engine.
Each world uses a new Qdrant collection; the collection name and learned atoms
are retained for inspection. Collections are not automatically deleted.

Both baselines use the existing `../normal-rag/normal_rag` components through
a B2 explanation adapter and run directly in the main benchmark process. RAG
embeds every sentence and the hypothesis using Ollama `nomic-embed-text`; its normalized
cosine retrieval defaults to four sentences. Full context skips indexing,
embeddings, retrieval, and Qdrant entirely. It needs the normal-RAG source and
chat credentials/provider access, with no PLN dependency or container.

| Option | Meaning/default |
|---|---|
| `--world-limit N` | Prefix of 1–42 worlds; default 42 |
| `--systems ...` | Any distinct selection of `pln_rag rag full_context` |
| `--run-id NAME` | New directory name under `artifacts/b2/` |
| `--output-dir PATH` | Alternative new run directory; must not already exist |
| `--top-k N` | Fixed RAG sentence limit, 1–25; default 4 |
| `--pln-top-k N` | Fixed native vector-entry limit; default 10 |
| `--pln-runtime docker\|local` | Default `docker` |
| `--container NAME` | Image source; default `pln-rag-pln-rag-1` |
| `--repo PATH` | Local PLN checkout; default `../PLN-RAG` |
| `--python PATH` | Local PLN interpreter; default launcher interpreter |
| `--normal-rag-repo PATH` | Baseline source; default `../normal-rag` |
| `--qdrant-url URL` | Overrides `B2_QDRANT_URL`, then `B1_QDRANT_URL` |
| `--ollama-url URL` | Overrides `OLLAMA_URL` |

Without a Qdrant setting, Docker uses `http://127.0.0.1:6333` and local mode uses
`http://127.0.0.1:16333`. B2 expects an existing service; it does not launch Qdrant.
The template's `B1_QDRANT_URL` points to port 16333, so set `B2_QDRANT_URL` or use
the CLI override when using the existing Docker services on port 6333.

The following optional B2 variables override the corresponding B1 values for
B2 only: `B2_MAX_LLM_CALLS`, `B2_LLM_MIN_INTERVAL`, `B2_LLM_TEMPERATURE`,
`B2_LLM_MAX_TOKENS`, `B2_LLM_TIMEOUT`, `B2_QUERY_TIMEOUT`, `B2_LEARN_TIMEOUT`,
`B2_REASONING_TIMEOUT`, and `B2_EMBEDDING_TIMEOUT`. Native reasoning timeout
must be a positive whole number of seconds. The default output ceiling is
2,000 tokens. Default deadlines are 900 seconds for PLN learning and 180
seconds for querying or answering. PLN workers have hard process-group
deadlines; baseline operations use an in-process timer in the main thread,
including indexing, request pacing and HTTP calls. The per-request LLM and
baseline embedding timeouts also remain in effect. See [.env.example](../.env.example).

## Task and isolation

The hypothesis already expresses the original science answer. The task is to
explain/support it with evidence, not recover a hidden answer or classify a
mixture of supported/unsupported targets. Every reference hypothesis is supported.

RAG and full context return the same small JSON contract:

```json
{"explanation": "The cited sentences support the hypothesis because ...", "evidence_ids": ["sent1", "sent2"]}
```

When support cannot be found, the explicit outcome is
`{"explanation": "", "evidence_ids": []}`. Malformed/truncated completions are
errors. Full context sends every sentence and ID without truncation; provider
context-window rejection is a failure. OpenRouter prompt-reduction transforms
are disabled. Successful construction of full context establishes input
coverage, not that the model used the evidence correctly.

PLN ingests one original sentence at a time through its native English parser,
store, and engine. Ingestion context includes earlier learned atoms. Native
retrieval uses a fixed limit of ten vector entries by default, which can return
multiple atoms per entry; parser enrichment includes up to 50 atoms from disk
and retrieval. The reasoner can access the entire learned per-world atomspace.
The manifest and native outputs record these distinct settings. They never
adapt to a world's gold proof or depth. Five native query candidates are allowed;
the upstream configured chaining-step limit is recorded but not claimed to be
enforced by the adapter. Hard process deadlines bound the operation.

The learned atom file is saved as a read-only, hashed snapshot. A fresh query
worker restores a verified copy, blocks parser-produced query statements and
knowledge/vector writes, and checks snapshot and before/after atomspace hashes.
The target hypothesis is absent from learning jobs. External background
knowledge and proof-to-answer generation are disabled. Native returned traces
are retained; an LLM does not rewrite them for evaluation.

Proof sources are resolved only through exact learned atom names in recognized
proof terms. Duplicate names across sentences, unmapped terms, and unrecognized
trace forms make the complete used-evidence measurement unavailable; partial
resolutions and raw traces remain inspectable. Retrieval mapping likewise
requires exact unambiguous atom matches. No semantic source guessing or official
whole-proof scorer is used. Parser acceptance is not semantic correctness.

Only sentence IDs/text, the target, and runtime settings enter operation jobs
and model requests. Original source records, intermediate conclusions, proof
leaves, distractor labels, depths, and question/answer metadata are used only by
the evaluator. The repository mount includes those files, so this is a validated
input boundary, not a filesystem security boundary. Neither Docker nor local
mode hides repository files from arbitrary native code. Learning workers
receive no hypothesis; query workers receive the hypothesis and verified
snapshot paths. Baselines receive public sentences and the hypothesis.

## Request budget and resources

| Selection | PLN chat estimate | RAG | Full context | Total |
|---|---:|---:|---:|---:|
| 42 worlds, all systems | 1,092 | 42 | 42 | 1,176 |
| First two, all systems | 52 | 2 | 2 | 56 |
| First two, full context only | — | — | 2 | 2 |

PLN estimates one parse per original sentence plus one hypothesis parse.
Parser formatting/chunking fallbacks can add calls. RAG uses 26 embedding calls
per world; native embedding work depends on its parser/chunker path. Full
context has zero embedding calls and typically more input tokens than top-four
RAG. Output limits are per-call ceilings, not total usage predictions.

One shared counter enforces the configured cap and request-start spacing across
all selected systems and PLN workers. The runner never raises the cap, even if
the estimate exceeds it.
OpenRouter defaults to 40 calls and four-second spacing when unset; free routes
require a finite cap and at least 3.1-second spacing. Other routes preserve the
B1 default of no cap when none is configured. Set an explicit cap suitable for
your account before running. A cap of 500 cannot cover the initial full estimate.
Execution is system first: by default all selected PLN worlds finish, then all
RAG worlds, then all full-context worlds. An explicit `--systems` order is
respected and recorded in the manifest. Earlier systems can exhaust the shared
budget and later records will be unattempted; the counter is never reset at a
system or process boundary.

Reports count observed HTTP attempts and separately show shared reservations
and audit coverage, including requests interrupted before a response. Reported
zero token counts remain zero; missing usage/model/provider fields remain
unmeasured. Learning/indexing and answering are timed separately. Answer time
includes pacing; each request retains its pacing wait and latency.

## Reading a run

Each live run writes a new `artifacts/b2/<run-id>/` directory:

| File/directory | Contents |
|---|---|
| `manifest.json` | Bundle hash, selected IDs, full/subset status, implementation revision/dirty state, settings, runtime image |
| `records.json` | Every selected system/world pair, including errors and unattempted work |
| `summary.json` | Overall and depth 1–7 metrics, world/record counts, measured/total coverage and reasons |
| `report.md` | Evidence/resource tables and paired RAG/full-context evidence results for each world |
| `llm_requests.json` | Combined request/response audits, returned model/provider and usage |
| `pln_rag/<world-id>/learn/` | Public learning job, output/log, request audits, partial learning, and `work/learned.metta` snapshot |
| `pln_rag/<world-id>/query/` | Public query job, output/log, request audits, verified working snapshot and native trace |
| `rag/<world-id>/`, `full_context/<world-id>/` | Public job/input, output/log, request/response audits and evaluated record |
| `pln_rag/<world-id>/record.json` | Evaluated PLN world result, including learning/query failures |
| `request_budget.json` | One shared reservation counter and request-start schedule |
| `pln_job.json`, `pln_records.json` | Public PLN supervisor job and durable raw world results, when PLN starts |
| `docker.launch.json`, `docker.log` | Single-container launch command and supervisor log, when Docker is used |
| `runtime.json` | Inspected Docker image ID and parser mount hashes, when used |

`PREPARED` is only a plan. `COMPLETE` means all selected operations returned
successfully, not that their evidence/proofs were correct. Errors or unattempted
pairs produce `COMPLETE_WITH_FAILURES` and CLI exit status 2. Interruptions retain
an `INTERRUPTED` report. Existing run directories are never overwritten.

Evidence precision/recall/F1 compare retrieved and used/cited IDs with the
annotated proof's input leaves. Duplicate citations are set-deduplicated;
unknown IDs and baseline citations to unseen sentences remain in the precision
denominator. Empty measured evidence scores zero. Unavailable evidence has a
reason and contributes to the total but not the measured mean. Always read the
measured/total counts alongside averages. Failures are not successful abstentions.

Supplied-context recall and all-gold inclusion describe available evidence.
Full context has no retrieval metrics; its constructed context recall is 1.0
even if answering later fails. For PLN, supplied-context coverage describes
source sentences with learned atoms accessible to the engine; it does not
certify that those atoms preserve the sentence meaning. The separately retained
`parser_context_mapping` describes the narrower query-parser input.
The gold-leaf count can be compared with RAG's sentence limit. That comparison
is unavailable for PLN because its limit counts vector entries, not original
sentences, and inference has wider atomspace access.

These are local evidence-overlap diagnostics, **not logical correctness or
official EntailmentBank proof accuracy**. Alternative valid evidence may differ.
The balanced subset does not represent the full source distribution. No
BLEURT, TensorFlow, NLTK download, checkpoint manager, or B1 logical oracle is
used. Offline tests establish implementation behavior, not live performance.
